# Leonardo (CINECA) Migration Runbook

Move the KS hard-state-sampling project from Bigfoot (OAR) to Leonardo booster (SLURM).
Everything heavy is **regenerated by seeded scripts** — only the repo travels.

Layout on Leonardo:
- repo: `$FAST/ogas_states` (venv inside at `.venv`)
- external deps: `$FAST/ogas_external/{al4pde,pdearena,jax-cfd}` (pinned clones)
- validation: `$FAST/ogas_validation/` (bank + `ks_diverse_suite/`)
- runs: `$FAST/ogas_states_runs/`

## 1. Move the repo (from your LOCAL workstation)

Leonardo is not reachable from Bigfoot — orchestrate from local. Two options:

**Via GitHub (preferred — the v3 work is committed and pushed):**
```bash
ssh leonardo 'cd $FAST && git clone https://github.com/CesarPierr/ogas_states.git'
```

**Via rsync two-hop (if the repo is ahead of the remote):**
```bash
rsync -az --exclude=.git --exclude=.venv --exclude='__pycache__' --exclude='OAR.*' \
  bigfoot:/home/cesarpi-ext/ogas_states/ /tmp/ogas_states/
rsync -az /tmp/ogas_states/ leonardo:'$FAST/ogas_states/'
```

## 2. Install + rebuild data (on Leonardo login node, ~1–2 h, no GPU needed)

```bash
ssh leonardo
cd $FAST/ogas_states
bash scripts/setup_leonardo.sh
```

This creates the venv, installs the pinned AL4PDE/pdearena/jax-cfd checkouts, generates
`configs/leonardo_ks_v3_base.yaml` (paths rewritten from /bettik to $FAST), regenerates the
KS validation bank (seeded ⇒ bit-comparable to Bigfoot's) and the diverse hard/tube suite,
and runs a 1-round CPU smoke test.

If torch reports `cuda=False` inside a GPU job, force the cu121 wheel:
```bash
.venv/bin/python -m pip install --force-reinstall --index-url https://download.pytorch.org/whl/cu121 torch==2.5.1+cu121
```

## 3. Launch the v3 pilot (6 arms × 1 seed)

```bash
cd $FAST/ogas_states
bash launch_v3_pilot_leonardo.sh     # account default: euhpc_d36_033 — override with LEONARDO_ACCOUNT
squeue -u $USER -o "%.10i %.25j %.10T %.10M %.20R"
```

Arms: `uniform_baseline`, `noise_inject`, `random_tube`, `mined_ic`, `gen_v3`, `gen_v3_edit`
(see HANDOFF.md for what each tests). A100 is ~the speed we sized rounds for; 10 rounds ≈ 2–4 h/job.

## 4. Move THIS Claude Code conversation

Claude Code sessions are plain files under `~/.claude/projects/<path-slug>/` on the machine
where the CLI runs (currently the Bigfoot login node, project slug `-home-cesarpi-ext-ogas-states`).
To carry the conversation + project memory to Leonardo (from local workstation):

```bash
# 1. Pull the session+memory dir off Bigfoot
rsync -az bigfoot:/home/cesarpi-ext/.claude/projects/-home-cesarpi-ext-ogas-states/ /tmp/ogas_claude/

# 2. Compute the Leonardo slug: absolute repo path with '/' -> '-'
LEO_PATH=$(ssh leonardo 'cd $FAST/ogas_states && pwd')
LEO_SLUG=$(echo "$LEO_PATH" | tr '/' '-')
echo "$LEO_SLUG"     # e.g. -leonardo_scratch-fast-euhpc_d36_033-<user>-ogas_states

# 3. Push it under the new slug
ssh leonardo "mkdir -p ~/.claude/projects/$LEO_SLUG"
rsync -az /tmp/ogas_claude/ leonardo:~/.claude/projects/$LEO_SLUG/
```

Then on Leonardo: `cd $FAST/ogas_states && claude` → `/resume` → pick this session.
The transcript (including the compacted history), the auto-memory (`memory/` with the
paper-direction / G1 / phase2 notes), and todos all come along. Fallback if resume
misbehaves: `HANDOFF.md` (committed) contains the full project state and is enough to
restart a fresh session with context.

## 5. What stays on Bigfoot

- The queued Bigfoot pilot (OAR 10910–10915) can keep running — results land in
  `/bettik/.../ks800_v3_pilot/` and remain analyzable there; no conflict with Leonardo runs.
- Phase 2/3 result archives and old run dirs stay on /bettik (only the small analysis
  tables matter for the paper; copy `poolbased_surrogate_validation/phase2_round10_analysis/`
  if needed: `rsync -az bigfoot:/bettik/.../phase2_round10_analysis /somewhere/`).
